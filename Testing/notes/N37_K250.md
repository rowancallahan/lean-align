## 2. Not done: the `twoGapCABG` range word kernel
Measured against: its letter `hamming` calls (`lim = 0`, stop at the first mismatch) cost ~312 Ir each inside
`ker16KWG` (113k calls, 35.3M; ~10 letters before the first mismatch), while one word scan's setup here was ~350–400
Ir before e2ba40a and is still ~150+ after it (`winOk`, the shifted first word, the loop entry). A word version
(e.g. `bwdA` from `B − 1` down to `A + 1`: no mismatch in `[A + 1, B − 1)` iff it returns `A + 1`) would cost about
the same or more on this data, and it needs `ker16KW` / `ker16KWG` changed in step plus a flags check one letter
outside `wordOk`'s window. Not worth it unless the matched ranges get longer.
