ALIGNER (new_spec/path/Aligner.lean, bounds design of 2026-10-27, vs codecs/TierRouter.lean TierOk /
tierPair_sound). Every answer: PairAnswer {found : Option PairReport, bestPossibleScore : Int,
uniqueness : unique | multimapper | unknown, tier : Tier (no claim)}, or trimmedAway. Claim
(PairAnswer.Correct): found is a real proper pair printed exactly; no proper pair scores above
bestPossibleScore; unique -> found is the unique best proper pair; multimapper -> found is a best
proper pair and another best proper pair sits at different placements. The previous tiered
version is kept in scratch (AlignerTiersBefore.lean) for reference.
 R1. CIGAR: reports must print real alignments (pair.report = report). STRONGER than old TierOk for
     T1/T1g/T1u/T2b (old had no CIGAR). Needs the router's CIGAR per reported mate from a correct
     alignment kernel at that placement/strand (AlignmentKernelCorrect + merged runs, A9).
 R2. How old tiers fill the answer, and what each needs:
     T1, T1g, T1u -> found = pair, bound = its score, unique. Old claims imply "unique best proper
       pair" (thresholds collapse: "at t and every looser threshold" includes all proper pairs;
       T1's two per-mate unique bests give the unique best pair).
     T1gm, T1um -> found = one of the tied best pairs, bound = its score, multimapper.
       NEW OBLIGATION: the router must report a tied pair, and the tie proof must name it and the
       second one (old PairTieOk only says no unique best exists among candidates).
     T2b -> found = pair, bound = its score (gap 0), unknown. From t2Opt_sound.
     T2 -> found = the pair in hand if proper (router must check properness), bound from the mates'
       floors / pfFloor, unknown.
     T3 -> found = none, bound from floors, unknown.
     T0 -> trimmedAway.
 R2b. TIER NAMES (for reporting: the tier goes in a custom output tag, with uniqueness and the bound).
     Old router tag -> Tier constructor -> what the answer holds -> freeze share (200k HiSeq/NovaSeq/mason):
       T1   -> eachMateUnique    -> found pair, bound = its score, unique        82.0 / 76.0 / 84.0 %
       T1g  -> quickSearchUnique -> found pair, bound = its score, unique         3.6 /  7.2 /  2.9 %
       T1u  -> deepSearchUnique  -> found pair, bound = its score, unique         0.5 /  0.9 /  2.0 %
       T1gm -> quickSearchTie    -> one tied pair, bound = its score, multimapper 1.8 /  2.3 /  0.7 %
       T1um -> deepSearchTie     -> one tied pair, bound = its score, multimapper 0.5 /  0.4 /  1.0 %
       T2b  -> bestUnchecked     -> found pair, bound = its score (gap 0), unknown 0.8 / 0.7 / 1.3 %
       T2   -> stoppedEarly      -> pair if proper, bound from floors, unknown    7.1 /  7.8 /  6.9 %
       T3   -> boundsOnly        -> no pair, bound from floors, unknown           3.7 /  4.6 /  1.4 %
       T0   -> (not a tier) PairResult.trimmedAway                                ~0 %
     Suggested reporting: found + unique -> mapped, high MAPQ; found + unknown -> mapped, MAPQ from
     the gap (bestPossibleScore - found score; 0 if the gap is 0 and it may tie); multimapper ->
     MAPQ 0 (or unmapped flag), the tied pair as the placement; no pair -> unmapped. Tags: tier,
     uniqueness, bestPossibleScore. -7 / -16 are the current search limits (stand-in values).

 R6. Inputs (2026-10-27): the spec's conclusion is about the useful types (Genome, Option Read); the
     bytes appear only in hypotheses: hGenome : file.decode = genome, hMate1/2 : bytes.map decodeRead
     = trimmed. alignPair : InsertSize → GenomeFile → (index : ByteArray) → Option ByteArray →
     Option ByteArray → PairResult is THE function the IO shim calls (comparator definition_names);
     no decoding happens at run time, so speed is unchanged. Adapter: decodeRead / GenomeFile.decode
     <-> the router's GenomeBytes / Encodes predicates (bytes < 256 is automatic for UInt8; catOk
     layout of the concatenated genome). Positions below 2^40 (Rowan's bound) go here as a
     hypothesis if the fixed-width code needs it.
 R7. INDEX: alignPair_correct assumes index = buildIndex genome (a hypothesis, not an axiom; a
     saved index is checked by hash in the IO shim). The router theorems assume the index checker
     passes (checkAll / checkAllMz); no theorem yet that the fast builders pass it. Options: prove
     builder -> checker passes, or have alignPair run the checker with a proved fallback.
 R6b. (2026-10-27, supersedes the alignPair parts of R6/R7) The one hole the shim calls is
     alignPairs : InsertSettings → (index : ByteArray) → List (Option ByteArray × Option ByteArray)
     → List PairResult, over a chunk of pairs. alignPair / alignPair_correct / alignPairs_chunks
     are gone. The genome bytes appear only in hGenome / hIndex: the index must carry the genome
     (as the freeze's pmap did: index files + saved packed genome .pgw/.pgx/.pgc, no FASTA at map
     time). Shim modes: `build GENOME.fa INDEX` (parseFasta + buildIndex + save) and `map INDEX ...`.
     Obligations:
       - buildIndex serializes MzIdx (.meta/.offs/.sl/.runs) + PGen (w, ex, n, o) + cuts (offs, ns)
         into one ByteArray; alignPairs reads them back.
       - SPEED RISK: alignPairs is called once per chunk with the whole index. Any per-call
         ByteArray.extract of the parts copies GBs per chunk. DECIDED (Rowan, 2026-10-27): the
         index stays one ByteArray (any layout can change later without a spec change); the
         kernels read the parts in place at offsets into the blob, and those reads get re-proved.
         Per-call cheap work (meta parse, mkIdx, cutAll, rdU64s of .runs) needs measuring
         against the 100k-pair chunk.
       - The freeze trusted a loaded index through `<pre>.hash` written after check3P passed
         (WG_CHECK=1). The new shim's map mode has only the TRUSTED comment; add the hash check back.
